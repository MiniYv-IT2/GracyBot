### 群聊消息发送修复

**问题**：Satori OneBot 适配器下，群消息 target 用了 `group:群号` 前缀，但 NapCat/Koishi 只认纯数字群号，导致 NapCat 收到 `target: (0)` 和 `rich media transfer failed`。

**修复**：`adapter.py` 中 channel_id 不做任何修饰，直接使用 `channel.id` 的纯数字（group）和 `private:QQ号`（private）区分。见 `adapter.py:_satori_event_to_gracy()`。

### 群聊图片发送修复

**问题**：使用 `Image.of(path="本地路径")` → SDK 转为 `file:///` URL → NapCat 无法读取 GracyBot 本地文件系统。

**修复流程**：
1. 替换为 `Image(src=data_url)`，将图片文件读取并转为 base64 data URL
2. 在 `gracy_to_satori()` 中：>200KB 图片自动 JPEG 压缩（75%质量，1280px 最大宽度）
3. >400KB 的 base64 字符串打 warning 日志
4. 保留 `media_base_url` 参数作为 HTTP URL 备用方案（当前未用）

**遗留问题**：图片发送 NapCat 仍显示 `target: (0)`，原因是 pipeline 中 SysInfo 等插件发消息时 `target` 传的是 `sender_id` 而非 `target_id`（旧风格插件 `data.get("group_id")` 取不到值）。已通过 `raw_data["group_id"]` 修复。

## get_platform_info() 重构

| 文件 | 改动 |
|---|---|
| `core/gracy_adapter/satori/adapter.py` | `_login_cache` 缓存 + `_on_account_update` 填充 |

**问题**：原实现中 `get_platform_info()` 调用 `account.protocol.login_get()`，但该方法是异步的，通过 `asyncio.run_coroutine_threadsafe()` 桥接 → 经常超时或返回空。

**修复流程**：
1. 连接建立时在 `_on_account_update()` 中 `await account.protocol.login_get()` 获取登录信息
2. 结果缓存到 `_login_cache`（user_id, nickname, avatar_url）
3. 调用 `friend.list`、`guild.list` 获取好友/群数量（可能因 Koishi 后端不支持而失败）
4. `get_platform_info()` 直接读缓存，不再走 sync-to-async 桥接
