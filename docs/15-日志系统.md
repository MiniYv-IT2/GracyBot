# 日志系统

## 日志分类

终端日志格式中的 `[分类]` 由 Logger 名称自动解析，规则如下：

| Logger 名 | 终端分类 | 示例 |
|---|---|---|
| `Core.xxx` | `[Core]` | `[Core] [Pipeline]` |
| `Adapter.xxx` | `[Adapter]` | `[Adapter] [QQOfficial.gateway]` |
| `Tool.xxx` | `[Tool]` | `[Tool] [Config]` |
| `Gracy.xxx` | `[Gracy]` | `[Gracy] [Help]` |
| `GracyUI` | `[GracyUI]` | `[GracyUI]` |

无前缀或未知 → 取第一个 `.` 前作为分类，兜底保留原名。

## 日志级别

| 级别 | 用法 |
|---|---|
| `INFO` | 正常流程记录 |
| `WARNING` | 可恢复的异常、降级 |
| `ERROR` | 功能不可用 |
| `CRITICAL` | 进程级故障 |
| `DEBUG` | 调试用（生产环境默认关闭） |

## 终端格式

```
{时间} - [{分类}] - {级别} - [{模块}] [{属性}] - {消息}
```

| 段 | 说明 |
|---|---|
| `时间` | `%Y-%m-%d %H:%M:%S` |
| `[分类]` | 见上表 |
| `{级别}` | INFO / WARNING / ERROR |
| `[模块]` | Logger 名的剩余部分 |
| `[{属性}]` | 可选的属性列表（P50 / 实例标识等） |
| `{消息}` | 开发者自由描述 |

### 示例

```
2026-06-23 15:05:10 - [Core] - INFO - [Security] - 审计日志 | 用户:xxx
2026-06-23 15:05:10 - [Core] - INFO - [Pipeline] - [适配器回调] 收到消息
2026-06-23 15:05:10 - [Adapter] - INFO - [QQOfficial.gateway] - WebSocket 连接成功
2026-06-23 15:05:10 - [Adapter] - INFO - [Send] - 消息发送成功
2026-06-23 15:05:10 - [Gracy] - INFO - [Help] - 收到 /help 命令
2026-06-23 15:05:10 - [Gracy] - INFO - [LLM_Chat.TTS] - 本地合成成功: xxx.wav (3.2s)
```

## 写日志的两种方式

两种方式等价，终端输出格式一致。

### 方式一：装饰器（推荐）

使用 `@with_logger` 自动注入 `self._logger`，用 `@log_attrs` 挂载属性：

```python
from core.decorators.logger import with_logger, log_attrs

@with_logger(category="Gracy")  # 自动 self._logger = logging.getLogger("Gracy.类名")
class MyPlugin:
    def __init__(self):
        self._logger.info("插件已初始化")
```

属性注入：

```python
@on_command("/help")
@log_attrs(priority="P50")
@plugin_handler
async def handler(ctx):
    _logger.info("收到命令")  # 终端自动带 [P50]
```

### 方式二：手动 getLogger

兼容旧插件，也适合无类场景：

```python
import logging
_logger = logging.getLogger("Gracy.MyPlugin")

_logger.info("消息")
_logger.warning("降级处理")
_logger.error("功能不可用: %s", e)
```

旧 logger 名（如 `LLM_Chat`、`Gracy.中文名`）自动兼容显示，不强制改名。

## 消息内容注意

logger 名已在 `[模块]` 位置显示，消息里不要重复模块名：

```python
# ❌ 重复
_logger.info("[QQOfficial] WebSocket 连接成功")

# ✅ 正确
_logger.info("WebSocket 连接成功")
```

## 属性机制

两种方式给日志行附加上下文属性（显示在 `[模块]` 和 `{消息}` 之间）：

```python
# 手动 extra
_logger.info("消息", extra={"log_attrs": {"priority": "P50"}})

# 装饰器
@log_attrs(priority="P50")
async def handler(ctx):
    _logger.info("消息")  # 自动带 priority
```

## 文件日志

`logs/gracybot.log` 格式与终端一致，仅不启用颜色。
