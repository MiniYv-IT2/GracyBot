## 安装与启动

### Q: `gracy` 命令找不到？

```bash
# 重新安装 CLI
cd gracybot
pip install . --force-reinstall --no-deps
```

### Q: WebSocket 连不上 NapCat？

```bash
# 1. 检查端口
netstat -ano | findstr :3001    # Windows
ss -tlnp | grep 3001             # Linux

# 2. 确认 config.json
# WS_MODE = "forward"
# WS_HOST = "127.0.0.1"
# WS_PORT = 3001
```

### Q: 启动时 `❌ 缺少必填字段: xxx`？

检查 `metadata.toml` 是否包含全部 9 个必填字段（name、version、author、description、entry、commands、chat_type、permission、is_at_required）。

### Q: `gracy stop` 无效？

```bash
# 手动查杀（Windows）
netstat -ano | findstr :3001
taskkill /f /pid <PID>

# 手动查杀（Linux）
pkill -f bot.py
```

## 插件开发

### Q: handler 没被调用？

```bash
gracy run --debug
# 看 [CommandMatcher] 日志是否匹配到命令
# 看 [PluginHandler] 日志是否执行
```

常见原因：

| 原因 | 现象 |
|---|---|
| TOML `commands` 写错 | 启动日志无此插件 |
| `chat_type` 不匹配 | 日志显示跳过此插件 |
| `permission = "master"` 非主人 | `跳过 xxx（仅主人可用）` |
| `is_at_required = true` 未 @ | 无日志，静默跳过 |

### Q: 新风格装饰器不工作？

```python
# 正确写法
@on_command("/cmd")     # ← @on_command 在外层
@plugin_handler          # ← @plugin_handler 在里层（紧贴函数）
async def handler(ctx: PluginContext):
    ...

# 错误写法（顺序颠倒 — 不报错但不会注册）
@plugin_handler
@on_command("/cmd")     # ❌
async def handler(ctx):
    ...
```

### Q: 怎么在插件中保存数据？

```python
import json
import os

DATA_FILE = os.path.join(os.path.dirname(__file__), "data.json")

def load():
    if os.path.exists(DATA_FILE):
        with open(DATA_FILE, "r", encoding="utf-8") as f:
            return json.load(f)
    return {}

def save(data):
    with open(DATA_FILE, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
```

## 调试与排错

### Q: 日志太多，想看特定插件的？

```bash
# Windows
Get-Content logs/gracybot.log -Tail 100 -Wait | Select-String "帮助插件"

# Linux
tail -f logs/gracybot.log | grep "帮助插件"
```

### Q: 插件报错不知道怎么排查？

1. 看 `[PluginHandler] 异常` 日志的 Traceback
2. 在本地单独运行测试函数
3. 用 `try/except` 打印详细错误到日志

```python
try:
    result = risky_function()
except Exception as e:
    import traceback
    _logger.error(f"错误: {e}\n{traceback.format_exc()}")
```

### Q: 启动后立刻退出？

```bash
# 看错误日志
cat logs/gracybot_error.log

# 常见原因
# 1. 端口被占用 → 改 config.json 端口
# 2. 插件导入报错 → 看异常追踪
# 3. config.json 格式错误 → 检查 JSON 语法
```

### Q: Hypercorn 启动后终端输出卡死/停止？

**症状：** Bot 消息正常处理（文件日志持续写入），但终端输出停在 `"面板已自启"` 附近，不再刷新。

**根因：** Python 的 `logging.StreamHandler(sys.stdout)` 在初始化时持有 `sys.stdout` 的**固定引用**。ASGI 服务器（Hypercorn/Quart）接管事件循环后，会劫持/重定向标准输出管道，`StreamHandler` 持有的旧引用写入到的是 Hypercorn 内部缓存，而非真实的 pipe/控制台。

**修复方式（logger_manager.py）：**

```python
# ❌ 旧代码 — StreamHandler 持有 sys.stdout 的固定引用
handler = logging.StreamHandler(sys.stdout)

# ✅ 新代码 — 自定义 Handler，每次 emit 用 print(flush=True)
#     print() 每次实时解析 sys.stdout，不受 ASGI 接管影响
class _ConsoleHandler(logging.Handler):
    def emit(self, record: logging.LogRecord) -> None:
        try:
            msg = self.format(record)
            print(msg, flush=True)
        except Exception:
            self.handleError(record)
```

**为什么 `print(flush=True)` 有效：**
- `StreamHandler` 构造时缓存了 `sys.stdout` 引用，Hypercorn 接管后该引用指向的内部 buffer 已失效
- `print()` 每次调用都通过 Python 运行时动态获取当前的 `sys.stdout`，Hypercorn 劫持不了这条路径

**验证方案：**
```bash
# 终端启动后，给机器人发一条消息
# 如果"面板已自启"之后还能看到"适配器回调 收到消息"等日志 → 修复成功
gracy run
```

## 性能与安全

### 频率限制配置

```python
# 新风格：60 秒内最多 5 次
@rate_limit(max_calls=5, period=60)
@plugin_handler
async def handler(ctx: PluginContext):
    ...
```

### 黑名单管理

```bash
# 在聊天中发送（主人专属）
/黑名单 添加 123456      # 拉黑用户
/黑名单 删除 123456      # 移除黑名单
/黑名单 列表             # 查看黑名单
```

### 安全建议

| 建议 | 说明 |
|---|---|
| 不硬编码 API Key | 使用 `config.json` 或环境变量 |
| 敏感操作加权限 | `@require_master` 限制 |
| 群聊命令尽量 @ | `is_at_required = true` |
| 日志脱敏 | 框架自动脱敏用户 ID |
