# 为插件在日志中注册启动信息

框架启动时会打印插件登记日志（由 PluginManager 统一输出）。这里讲的是**插件如何在日志中注册自己的启动信息**。

---

## 插件的三种启动注册方式

### 方式一：register_on_ready

框架初始化完成后触发。插件注册的回调函数自己打印启动日志。

```python
from graci import plugin_manager

def on_boot():
    _logger.info("后台服务已启动，端口: 5090")

plugin_manager.register_on_ready(on_boot)
```

日志输出（出现在适配器启动之后）：

```
[Gracy.插件名] - INFO - 后台服务已启动，端口: 5090
[Gracy.插件名] - INFO - 服务自启完成，通知已发送
```

特点：
- 适配器、Pipeline 已就绪后才执行
- 日志由插件自己的回调打印
- 适合 Web 面板、后台定时任务等

### 方式二：模块级自执行

import 插件入口文件时直接调用初始化函数，不依赖框架调度。

```python
# 插件入口文件.py
from .engine import initialize  # initialize() 由插件自己定义
initialize()  # ← 模块级直接调用
```

`initialize()` 不在框架 core 中定义，由插件自身实现（如 `Gracone_Plugin/gracone_core.py` 第 418 行的 `def initialize()`）。框架不调度它，它在 import 时自动执行。

日志输出（早于其他插件）：

```
[插件Logger名] - 引擎 v1.0.0 初始化完成 — 已加载 2 个子模块
[插件Logger名] - INFO - 已加载子模块: module_a
[插件Logger名] - INFO - 已加载子模块: module_b
```

特点：
- 在框架的插件注册循环**之前**执行
- 日志由插件模块顶层代码直接打印
- 适合兼容层、需要在框架注册前注入命名空间的场景

### 方式三：懒加载

插件 handler 在收到第一次消息时才初始化引擎，启动时没有任何初始化日志。

```
第一次收到消息时：
[Gracy.插件名] - INFO - 引擎加载成功，模型已就绪
```

特点：
- 启动阶段无日志（只有框架的 handler 登记行）
- 初始化日志在运行时才出现
- 适合启动耗时的场景（如 AI 模型加载）

---

## 三种方式的启动日志出现顺序

```
[GracyBot] - INFO - 日志系统初始化完成                 ← 框架
[插件自执行] - 引擎初始化完成                         ← 模块级自执行
[Gracy] - INFO -   其他插件注册 handler=...            ← 框架登记（非插件自注册）
[Adapter] - INFO - 适配器连接成功                      ← 适配器
[插件OnReady] - 后台服务已启动                        ← on_ready 触发
```

| 方式 | 调用方 | 执行时机 | 启动阶段有无日志 |
|------|-------|---------|---------------|
| register_on_ready | 插件回调 | 适配器就绪后 | 有（适配器启动后出现） |
| 模块级自执行 | 模块顶层 | import 时 | 有（早于框架插件登记） |
| 懒加载 | handler 内部 | 收到消息时 | 无（运行时才出） |
