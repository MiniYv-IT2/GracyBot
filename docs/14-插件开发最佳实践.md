## 核心理念

```
插件只做一件事：处理业务逻辑。
发送、接收、文件上传、权限校验——全部交给框架和适配器。
```

好的插件应该：
- **平台无关** — 换 QQ 官方适配器或 OneBot 适配器都能跑
- **适配器无关** — 不 import 任何 `qq_official`、`onebot` 下的模块
- **路径无关** — 不用死人路径，不用 Linux-only 路径
- **配置外置** — API Key、开关等不进代码
- **日志独立** — 不破坏框架日志体系

## 第一原则：永不触碰适配器

### ❌ 错误（侵染适配器）

```python
from core.gracy_adapter.qq_official.api import QQOfficialAPI
# 或
from core.gracy_adapter.send import gracy_send_msg
# 或
from core.adapter import adapter_pool
```

### ✅ 正确（只通过 ctx）

```python
from core.decorators import on_command, plugin_handler, PluginContext

@on_command("/hello")
@plugin_handler
async def handler(ctx: PluginContext):
    await ctx.reply("你好")                    # 文本
    await ctx.send(GracyImage(file_path="x.png"))  # 图片
```

### 为什么

- 适配器可能换（OneBot ↔ QQ 官方）、可能新增
- 插件直接调 `gracy_send_msg` 绕过 ctx，会丢失多账号路由上下文
- 平台特有的消息格式（如 CQ 码、QQ 官方的 media）不应该出现在插件里

## 第二原则：通过 ctx 收发消息

### 发消息只用这些

| 方法/类 | 用途 |
|---------|------|
| `ctx.reply(text)` | 回复纯文本 |
| `ctx.send(seg1, seg2, ...)` | 发送任意组合消息 |
| `ctx.finish(text)` | 发送并终止处理 |
| `GracyText(text="")` | 文字消息段 |
| `GracyImage(file_path="")` | 图片（本地路径） |
| `GracyImage(url="")` | 图片（公网 URL） |
| `GracyImage(file_data=b"")` | 图片（二进制数据） |
| `GracyVoice(file_path="")` | 语音（本地路径） |
| `GracyAt(target_id="")` | @某人 |
| `GracyReply(message_id="")` | 引用回复 |

### 不要做的事

```python
# ❌ 直接用适配器发送
from core.gracy_adapter.send import gracy_send_msg
await gracy_send_msg(target, GracyText("hi"), chat_type="group")

# ❌ 构造适配器专用 payload
payload = {"msg_type": 7, "media": {"file_info": "xxx"}}

# ❌ 手动调用上传接口
from core.gracy_adapter.qq_official.media import MediaMixin
```

## 第三原则：路径不硬编码

### ❌ 错误写法

```python
# Linux 写死
engine_path = "/usr/bin/fairy-stockfish"

# Windows 写死
cache_dir = "C:\\Users\\admin\\cache"

# 相对路径依赖 CWD
with open("data/xxx.txt") as f:
```

### ✅ 正确写法

```python
import os

# 插件自身目录（永远正确）
PLUGIN_DIR = os.path.dirname(os.path.abspath(__file__))
CACHE_DIR = os.path.join(PLUGIN_DIR, "data", "cache")
DATA_DIR = os.path.join(PLUGIN_DIR, "data")

# 需要用户配置的路径 → 走 config
# 在 config.py 中定义 DEFAULT_CONFIG
# 用户配置后通过 plugin_manager.get_plugin_config() 读取
```

### 工具函数备忘

```python
os.path.join(a, b)       # 跨平台路径拼接（自动 / 或 \\）
os.path.exists(path)     # 判断是否存在
os.makedirs(path, exist_ok=True)  # 创建目录（安全）
# 不要用：
# os.system("mkdir -p")  ← Linux only
# path + "/" + name     ← Windows 会炸
```

## 第四原则：配置集中管理

### 配置定义（`config.py`）

```python
"""插件配置"""
from typing import Dict, Any

DEFAULT_CONFIG: Dict[str, Any] = {
    "apikey": "",           # API 密钥（用户自行填写）
    "api_url": "https://...",  # API 端点
    "timeout": 10,          # 超时秒数
    "cache_max_days": 7,    # 缓存清理天数
    "max_results": 10,      # 最大结果数
    "proxy": "",            # 代理（可选）
}
```

### 读取配置（`YourPlugin.py`）

```python
from core.plugin_manager import plugin_manager

def _load_config() -> dict:
    return plugin_manager.get_plugin_config("YourPlugin")

# 使用
cfg = _load_config()
apikey = cfg.get("apikey", "")
api_url = cfg.get("api_url", "https://default-url.com")
```

### 配置要点

- **API Key 不进代码** — 永远从配置读取
- **提供默认值** — `cfg.get("key", "默认值")`，配置缺失也不崩
- **只读不写** — 插件不要写回配置，用户自己改 `config.json`
- **敏感信息不日志** — 不要在日志里打 `apikey`、`token`、`password`

## 第五原则：正确的日志

### ✅ 标准写法

```python
import logging
_logger = logging.getLogger("Gracy.我的插件")
```

### 注意

- Logger 名固定格式：`Gracy.插件名`
- 插件名保持唯一（用 `metadata.toml` 中的 `name` 字段）
- 只记录**必要信息**（开始、结束、异常、关键结果）
- 不记录敏感信息（API Key、Token、密码）
- 异常用 `exc_info=True` 而非只打 `str(e)`

```python
# ✅ 好
_logger.info(f"[搜索] 关键词: {keyword}, 找到 {len(results)} 条")
_logger.error(f"[API] 请求失败: {e}", exc_info=True)

# ❌ 不好
_logger.debug(f"apikey={apikey}")
_logger.error(f"出错: {e}")  # 只有消息没有堆栈
```

## 第六原则：跨平台兼容

### Python 标准库优先

```python
import os
import sys

# ✅ 路径拼接
path = os.path.join("dir", "file.txt")

# ❌ Linux only
path = "dir/file.txt"

# ✅ 判断平台
if sys.platform == "win32":
    # Windows 特殊处理
    pass
```

### 外部依赖注意

| 依赖 | 跨平台 | 说明 |
|------|--------|------|
| `httpx` / `aiohttp` | ✅ | HTTP 请求，全平台 |
| `Pillow` | ✅ | 图片处理 |
| `playwright` | ✅ | 浏览器截图，但注意：**不要硬编码浏览器路径** |
| `sqlite3` | ✅ | Python 内置 |
| subprocess 调用 | ⚠️ | 确保命令在目标平台存在 |

### 子进程调用（必须做平台判断）

```python
import sys, subprocess

if sys.platform == "win32":
    proc = await asyncio.create_subprocess_exec(
        "engine.exe", ...)
else:
    proc = await asyncio.create_subprocess_exec(
        "./engine", ...)
```

## 第七原则：资源文件管理

### 文件存储规范

```
plugins/YourPlugin/
├── data/
│   ├── cache/          # 运行时缓存（可清理）
│   └── background/     # 静态资源（不可清理）
├── resources/          # 内置图片/字体等
└── config.py           # 配置定义
```

### 缓存文件管理

```python
import os, time

CACHE_DIR = os.path.join(PLUGIN_DIR, "data", "cache")

def clean_old_cache(max_days: int = 7):
    """清理超过 N 天的缓存文件"""
    if not os.path.isdir(CACHE_DIR):
        return
    now = time.time()
    for fname in os.listdir(CACHE_DIR):
        fpath = os.path.join(CACHE_DIR, fname)
        if os.path.isfile(fpath):
            age = now - os.path.getmtime(fpath)
            if age > max_days * 86400:
                os.remove(fpath)
```

### 临时文件使用 `tempfile`

```python
import tempfile

# ✅ 自动清理
with tempfile.NamedTemporaryFile(suffix=".png", delete=False) as tmp:
    tmp.write(image_data)
    tmp_path = tmp.name

try:
    # 使用 tmp_path
    await ctx.send(GracyImage(file_path=tmp_path))
finally:
    os.unlink(tmp_path)  # 用完必删
```

## 检查清单

写插件时逐条核对：

### 基础
- [ ] `metadata.toml` 中 `name` 唯一
- [ ] 遵循 5 层导入顺序
- [ ] Logger 名称为 `Gracy.插件名`
- [ ] 不使用 `from core.utils import logger`

### 适配器隔离
- [ ] 不 import 任何 `gracy_adapter/qq_official/` 模块
- [ ] 不 import 任何 `gracy_adapter/onebot/` 模块
- [ ] 不直接调 `gracy_send_msg`
- [ ] 不直接调 `adapter_pool`
- [ ] 只通过 `ctx.reply()` / `ctx.send()` 发消息

### 路径
- [ ] 不使用 `"/"` 拼接路径
- [ ] 不使用 Linux-only 路径（`/usr/bin/`、`/tmp/`）
- [ ] `os.path.join()` 拼接，`os.makedirs(exist_ok=True)` 创建
- [ ] 临时文件用 `tempfile` + `finally` 清理

### 配置
- [ ] API Key 等敏感信息从 `plugin_manager.get_plugin_config()` 读取
- [ ] `DEFAULT_CONFIG` 中每个字段都有合理的默认值
- [ ] 敏感信息不日志

### 跨平台
- [ ] 硬编码路径做了平台判断
- [ ] 外部命令调用了正确的平台版
- [ ] 使用 `sys.platform` 判断而非 `os.name`

### 错误处理
- [ ] 网络请求有 try/except
- [ ] 异常日志用 `exc_info=True`
- [ ] 用户有错误提示（不直接抛给用户看堆栈）
