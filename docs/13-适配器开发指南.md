## 架构概述

GracyBot 采用**适配器层解耦**设计，框架核心（`core/`）不依赖任何具体平台协议。新增平台只需：

1. 在 `core/gracy_adapter/` 下新建目录
2. 实现 `GracyAdapter` 抽象基类
3. 提供 `create_adapter()` 工厂函数
4. 用户创建实例配置文件

框架通过 `importlib` 动态加载适配器，**无需修改 `core/main.py`**。

```
┌──────────────────────────────────────────────────┐
│                    插件层                         │
│  plugins/  ──  业务逻辑，平台无关                  │
├──────────────────────────────────────────────────┤
│                    框架层                         │
│  Pipeline  ──  消息调度，安全校验，命令分发         │
│  core/main.py ──  动态加载适配器，零硬编码          │
├──────────────────────────────────────────────────┤
│                    适配层                         │
│  GracyAdapter ──  统一事件/消息格式，平台无关       │
│  onebot/  QQPersonal/  ... ──  按需接入           │
└──────────────────────────────────────────────────┘
```

## 配置文件规范

### 配置文件位置

```
style/instances/<实例名>/config.json
```

每个机器人账号一个实例目录，例如：
- `style/instances/onebot_main/config.json` — OneBot 主号
- `style/instances/qq_official/config.json` — QQ 官方机器人
- `style/instances/telegram_bot/config.json` — Telegram 机器人

### 必填字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `platform` | str | 平台标识，必须与适配器目录名一致 | `"qq_official"` |
| `bot_name` | str | 实例名称，用于日志和事件溯源 | `"官方机器人"` |
| `enabled` | bool | 是否启用，false 则启动时跳过 | `true` |
| `robot_id` | str | 机器人 ID（格式由平台决定） | `"openid_xxx"` |
| `master_id` | str | 主人/管理员 ID | `"192004908"` |

### 可选字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| 平台特定字段 | any | 各适配器按需定义 | `app_id`, `app_secret` 等 |

### OneBot 实例配置示例

```json
{
  "platform": "onebot",
  "bot_name": "主号",
  "enabled": true,
  "robot_id": "2694283261",
  "master_id": "192004908",
  "type": "http",
  "http_url": "http://127.0.0.1:3000",
  "callback_port": 3002
}
```

### QQ 官方实例配置示例

```json
{
  "platform": "qq_official",
  "bot_name": "官方机器人",
  "enabled": true,
  "robot_id": "官方机器人openid",
  "master_id": "192004908",
  "app_id": "QQ开放平台AppID",

```

### 配置加载流程

```
启动 gracy run
    │
    ▼
core/main.py: _discover_instance_configs()
    │ 扫描 style/instances/ 目录
    ▼
读取每个 <实例名>/config.json
    │
    ▼
过滤 enabled=false 的实例
    │
    ▼
_register_instance(cfg) → 动态加载适配器
```

## 核心接口

### GracyAdapter 抽象基类

**文件**：`core/gracy_adapter/adapter.py`

所有适配器必须实现以下 4 个抽象方法：

```python
from abc import ABC, abstractmethod
from typing import Callable, List, Optional

from core.gracy_adapter.event import GracyEvent
from core.gracy_adapter.identity import IdentityTag
from core.gracy_adapter.message import GracyMsg


class GracyAdapter(ABC):
    """适配器抽象基类"""

    @abstractmethod
    def start(self, on_event: Callable[[GracyEvent], None]) -> None:
        """启动适配器，开始监听消息

        Args:
            on_event: 收到消息时的回调，传入 GracyEvent
        """
        ...

    @abstractmethod
    def send(self, target: str, segments: List[GracyMsg], chat_type: str) -> bool:
        """发送消息到指定目标

        Args:
            target: 目标 ID（格式由平台决定）
            segments: 结构化消息段列表
            chat_type: "private" | "group"

        Returns:
            发送成功返回 True
        """
        ...

    @abstractmethod
    def stop(self) -> None:
        """停止适配器，释放资源"""
        ...

    @abstractmethod
    def get_platform_info(self) -> dict:
        """获取平台/机器人统计信息

        必须返回以下统一结构，不支持的字段填 None：
        {
            "friend_count": int | None,     # 好友/联系人数量
            "group_count": int | None,      # 群组/频道数量
            "platform": str,                # 平台标识，如 "OneBot" / "QQOfficial"
            "protocol_version": str | None, # 协议端版本
        }
        """
        ...
```

### 可选方法

```python
    def call_api(self, action: str, params: dict = None) -> Optional[dict]:
        """通用 API 调用（可选）

        默认返回 None，表示不支持。
        平台特有 API（如 OneBot 的 send_like）在此实现。

        Args:
            action: API 名称
            params: 参数字典

        Returns:
            成功返回 data 字段，失败返回 None
        """
        return None
```

### IdentityTag 属性

适配器注册时由框架自动设置，也可在 `__init__` 中手动设置：

```python
@property
def tag(self) -> Optional[IdentityTag]:
    """获取适配器身份标签"""
    return getattr(self, '_tag', None)

@tag.setter
def tag(self, value: IdentityTag) -> None:
    """设置适配器身份标签"""
    self._tag = value
```

`IdentityTag` 的字段：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `platform` | str | 平台标识 | `"onebot"` |
| `bot_name` | str | 实例别名 | `"主号"` |
| `conn_type` | str | 连接方式，由工厂函数自动设置 | `"WS (反向)"` / `"HTTP"` / `"WebSocket Gateway"` |
| `instance_id` | str | 8 位短 UUID，保证唯一性 | `"a1b2c3d4"` |

`tag.conn_type` 的值来源于工厂函数中设置的 `adapter.conn_type_display`（见下文）。该字段会在 `/关于` 指令输出中展示，方便区分不同连接模式。

## 工厂函数

### 必须提供

每个适配器的 `adapter.py` 必须导出 `create_adapter()` 函数：

```python
def create_adapter(config: dict) -> GracyAdapter:
    """工厂函数：根据实例配置创建适配器实例

    Args:
        config: 实例配置字典（来自 style/instances/<name>/config.json）

    Returns:
        适配器实例
    """
    return <Platform>Adapter(
        app_id=config.get("app_id", ""),
        app_secret=config.get("app_secret", ""),
        is_sandbox=config.get("is_sandbox", False),
        robot_id=config.get("robot_id", ""),
    )
```

### 框架调用方式

```python
# core/main.py 中的动态加载逻辑
import importlib

platform = cfg.get("platform", "onebot")
module = importlib.import_module(f"core.gracy_adapter.{platform}.adapter")
create_fn = getattr(module, "create_adapter")
adapter = create_fn(cfg)
```

### 额外字段：`conn_type_display`

工厂函数应在创建适配器实例后，根据配置中的连接类型设置 `adapter.conn_type_display`。该值会被框架写入 `IdentityTag.conn_type`，在 `/关于` 指令和启动日志中展示。

OneBot 示例：

```python
def create_adapter(config: dict) -> GracyAdapter:
    raw_type = config.get("type", "http")
    # 根据 type 设置连接方式显示名
    if raw_type in ("ws_reverse", "reverse"):
        conn_type = "WS (反向)"
    elif raw_type == "ws_forward":
        conn_type = "WS (正向)"
    else:
        conn_type = "HTTP"

    adapter = OneBotAdapter(...)
    adapter.conn_type_display = conn_type
    return adapter
```

框架会自动将其同步到 `IdentityTag.conn_type`，无需额外操作。

## 与 core 核心对接流程

### 完整注册流程

```
1. 启动 → _discover_instance_configs()
   │  扫描 style/instances/ 目录，读取所有 config.json
   │
2. _register_instance(cfg)
   │  根据 platform 字段动态 import 适配器模块
   │  调用 create_adapter(cfg) 创建实例
   │
3. adapter.tag = IdentityTag(platform, bot_name)
   │  设置适配器身份标签
   │
4. adapter._instance_master_id = master_id
   │  挂上主人 ID（用于权限校验）
   │
5. adapter._instance_robot_id = robot_id
   │  挂上机器人 ID（用于多账号路由）
   │
6. adapter_pool.register(adapter, tag, default=is_first)
   │  注册到适配器池
   │
7. adapter.start(on_event=event_bus.publish)
   │  启动适配器，开始监听消息
```

### 关键对接点

| 对接点 | 说明 | 位置 |
|--------|------|------|
| **事件回调** | `start(on_event)` 传入的回调函数 | `core/main.py` |
| **消息路由** | 通过 `self_id` 匹配适配器实例 | `_get_parser_by_self_id()` |
| **Runtime 上下文** | Pipeline 处理时自动绑定 | `core/runtime.py` |
| **发送路由** | `gracy_send_msg()` 自动走对应适配器 | `core/gracy_adapter/send.py` |

## 消息收发链路

### 入站链路（接收消息）

```
平台推送（WebSocket / WebHook）
    │
    ▼
适配器.parse_event(raw_data)
    │  将平台原始数据转换为 GracyEvent
    ▼
GracyEvent（平台无关格式）
    │
    ▼
EventBus.publish(event)
    │  异步发布到事件总线
    ▼
Pipeline.process(event)
    │  5 个 Stage 顺序执行
    ▼
Plugin handler（插件处理）
```

### 出站链路（发送消息）

```
插件 ctx.reply(text) / ctx.send(*segments)
    │
    ▼
gracy_send_msg(target, *segments, chat_type)
    │  从 RuntimeContext 获取当前适配器 tag
    ▼
adapter_pool.send(target, segments, chat_type, tag)
    │  查找对应适配器
    ▼
adapter.send(target, segments, chat_type)
    │  适配器实现的消息发送
    ▼
平台 API（HTTP POST / WS 发送）
```

### 多实例路由

```
消息到达 → 提取 self_id → 匹配适配器 → 绑定 Runtime → 插件处理 → 回复走对应适配器
```

插件无需关心多账号逻辑，Pipeline 自动适配。

## 最佳实践

### 日志规范

```python
import logging
_logger = logging.getLogger(f"Gracy.{platform}")
```

日志格式：`[<Platform>] 消息内容`

### 异步要求

- 所有网络操作必须使用 `asyncio` + `aiohttp`
- 禁止使用 `requests`、`time.sleep`、`threading`
- WebSocket 连接使用 `websockets` 库

### 错误处理

- 发送失败返回 `False`，不抛异常
- 连接断开自动重连（指数退避）
- 记录错误日志，不阻塞主流程

### 资源管理

- `stop()` 中关闭所有连接和会话
- 使用 `asyncio.ensure_future()` 异步清理
- 避免内存泄漏（清理缓存、关闭连接）

### 配置校验

```python
def create_adapter(config: dict) -> GracyAdapter:
    # 校验必填字段
    if not config.get("app_id"):
        raise ValueError("缺少必填字段: app_id")
    if not config.get("app_secret"):
        raise ValueError("缺少必填字段: app_secret")

    return <Platform>(...)
```
